# MARK 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to follow this plan task-by-task. This project is learner-led: explain each concept, give only the current exercise, and wait for the learner's attempt before reviewing or revealing implementation code.

**Goal:** Establish a reproducible Python 3.11 environment and build a learner-written OpenCV program that reads, inspects, transforms, displays, and safely releases local camera frames.

**Architecture:** MARK 0 is intentionally a single local Python learning slice. Camera acquisition and elementary frame transformations will be learned first; reusable abstractions are deferred until real duplication or MARK I requirements justify them.

**Tech Stack:** macOS arm64, Homebrew, CPython 3.11, `venv`, NumPy, OpenCV, pytest

**Spec:** `docs/PROJECT_CONTEXT.md` and the MARK 0 section of `ROADMAP.md`

## Global Constraints

- Use Python 3.11 on the Apple Silicon development Mac.
- Process camera frames locally; do not upload or implicitly save them.
- Do not introduce MediaPipe, PySide6, ESP32 tooling, networking, or web technology during MARK 0.
- Give the learner one small exercise at a time and review their attempt before moving forward.
- Do not advance to MARK I until every MARK 0 acceptance criterion passes.

## Planned File Structure

- `.gitignore`: excludes the virtual environment, Python caches, local captures, IDE files, and secrets.
- `pyproject.toml`: records project metadata, Python 3.11 compatibility, and MARK 0 dependencies after they are understood.
- `src/arc_room_hub/__init__.py`: defines the initial Python package boundary.
- `src/arc_room_hub/mark0_camera.py`: learner-written MARK 0 camera loop and frame inspection exercise.
- `tests/test_mark0_frame.py`: tests deterministic frame transformations without requiring a camera.
- `LEARNING_LOG.md`: records concepts, evidence, questions, and the next exercise.

The files above are planned, not pre-authorized implementations. Create them only in the task that needs them and preserve the learner-first workflow.

### Task 1: Python 3.11 Environment

**Files:**

**Produces:** A project-local virtual environment whose interpreter reports CPython 3.11 on `arm64`.

### Task 3: Understand a Frame Without a Camera

**Files:**

- Create: `tests/test_mark0_frame.py`
- Create or modify: `src/arc_room_hub/mark0_camera.py`
- Modify: `LEARNING_LOG.md`

**Interfaces:**

- Produces: A small pure transformation function that consumes a `numpy.ndarray` and returns a transformed `numpy.ndarray`; its exact name and first transformation are selected during the exercise.

- [ ] **Step 1: Explain the frame data model**

Use a tiny synthetic array to teach shape `(height, width, channels)`, `uint8`, row/column indexing, pixel values, and BGR channel order.

- [ ] **Step 2: Give one array exercise**

Ask the learner to create a small NumPy frame, inspect its shape and data type, and predict one indexed pixel before running it.

- [ ] **Step 3: Review the result**

Check dimension order, indexing, channel assumptions, and whether the learner can explain each printed value.

- [ ] **Step 4: Write one failing transformation test together**

Choose exactly one transformation—grayscale, crop, resize, or BGR-to-RGB—and define its expected output shape and type before implementing it.

- [ ] **Step 5: Run the focused test and observe the expected failure**

```bash
python -m pytest tests/test_mark0_frame.py -v
```

Expected: failure caused by the not-yet-implemented transformation, not by import or environment errors.

- [ ] **Step 6: Let the learner implement the minimum transformation**

Review their attempt for correctness, input assumptions, and unnecessary complexity before suggesting edits.

- [ ] **Step 7: Re-run the focused test**

```bash
python -m pytest tests/test_mark0_frame.py -v
```

Expected: pass with no physical camera required.

- [ ] **Step 8: Record and commit the learning checkpoint**

```bash
git add src/arc_room_hub/mark0_camera.py tests/test_mark0_frame.py LEARNING_LOG.md
git commit -m "test: learn deterministic frame transformation"
```

### Task 4: Learner-Written Camera Loop

**Files:**

- Modify: `src/arc_room_hub/mark0_camera.py`
- Modify: `LEARNING_LOG.md`

**Consumes:** The NumPy frame model and transformation learned in Task 3.

**Produces:** A local camera program that validates reads, inspects a frame, displays live output, responds to an intentional exit action, and always releases resources.

- [ ] **Step 1: Explain the camera lifecycle**

Explain open, read, validate, process, display, poll for exit, and cleanup. Introduce `try/finally` as the guarantee that cleanup runs after normal exit or an error.

- [ ] **Step 2: Ask the learner for pseudocode**

Review the control flow before any OpenCV camera code is written.

- [ ] **Step 3: Let the learner write the basic loop**

Do not provide the complete implementation. Give one hint at a time for camera opening, `read()` validation, frame inspection, display, keyboard exit, and cleanup.

- [ ] **Step 4: Review the program specifically**

Check camera-open validation, the boolean returned by `read()`, accidental repeated logging, event polling, exit behavior, and cleanup under `finally`.

- [ ] **Step 5: Run the local manual demonstration**

```bash
python -m arc_room_hub.mark0_camera
```

Expected: local live video appears, requested frame metadata is observable, intentional exit works, and the camera is immediately reusable afterward.

- [ ] **Step 6: Exercise one controlled failure**

Use an invalid camera index or deny availability without changing system security settings. Expected: a clear local error and clean termination without an orphaned window or locked camera.

- [ ] **Step 7: Record and commit the evidence**

```bash
git add src/arc_room_hub/mark0_camera.py LEARNING_LOG.md
git commit -m "feat: complete learner-written mark 0 camera loop"
```
